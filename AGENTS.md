# ExternalApi agent instructions

- Use the shared [standards adoption skill](../invensys.docs/.agents/skills/invensys-standards-adoption/SKILL.md) for standards alignment and verification.
- Read the shared [environment patterns](../invensys.docs/.agents/skills/invensys-environment-patterns/SKILL.md) for configuration, authentication boundaries, and delivery, and [backend patterns](../invensys.docs/.agents/skills/invensys-dotnet-patterns/SKILL.md) for .NET, integration clients, and telemetry. Load only references relevant to the task and preserve this repository's existing integration-library architecture and public contracts.
- Keep reusable skill definitions in invensys.docs. Do not add or copy local skills into this repository. If local skills are discovered, ask the user before consolidating their guidance into the shared library.
- Do not create or expand public/root or component README files unless the user explicitly requests a README edit. API usage must be apparent from XML summary comments in the API source/interface files. Put UI examples in demo pages and internal guidance in invensys.docs.
- Prettier may handle only .scss, .ts, and .html files if present. Do not apply it to C#, JavaScript, JSON, Markdown, YAML, or other file types.
- Preserve existing work. Shared guidance does not authorize unrelated sibling edits, deployment, publishing, database resets, or changes to credentials.
- Parameter names must follow their types and the established API naming: `JwtAccessTokenRequest accessTokenRequest`, `CreateEmployeeRequest createEmployeeRequest`, and `CreatePositionRequest createPositionRequest`. Keep names identical between interfaces, implementations, XML documentation, and named arguments. Do not introduce aliases such as `credentials`, `employee`, or `position` for these typed parameters.
- Use Ardalis.GuardClauses for argument/precondition validation. Use `Guard.Against.Null`, `NullOrWhiteSpace`, `OutOfRange`, or `InvalidInput` rather than framework `Argument*Exception.ThrowIf*` helpers or manual argument-check/throw blocks. Preserve validation behavior and exception contracts; cancellation checks and domain/HTTP errors remain separate.
